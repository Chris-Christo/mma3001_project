## Evaluation choices fixed before final testing

- Building space: `227f1068-9e41-469f-bef0-275f27a0bdba`.
- Training: March 2024–August 2025; validation: September–December 2025; testing: January–March 2026.
- Thirty-minute nominal forecast horizon and five-minute backward matching allowance.
- Same prepared examples, five conceptual inputs and 11 encoded columns as Notebooks 4–5.
- Persistence has no fitting. Linear regression and SVR are reconstructed using their original training data and recorded parameters, not a combined training/validation set.
- Reconstructed validation forecasts must agree with saved forecasts before test data is loaded.
- Model selection: minimum validation MAE, then RMSE, then model name for exact ties.
- All three prespecified methods receive a test score. Those scores do not change the selected method or its parameters.
- Raw fractional/negative predictions are retained. No output policy is chosen using test results.
- Monthly test scores, negative forecasts, mean residual, error direction, runtime and the first test week are reported as descriptive diagnostics.

The protocol is written to `outputs/227f1068/comparison/evaluation_protocol.json` before test loading. `test_exposure_record.json` records the first execution time and the protocol/test-file fingerprints. These are transparent audit records, not tamper-proof guarantees. Reproducing the same experiment is allowed and is labelled as a repeat. A changed protocol after exposure stops the notebook; do not delete records merely to enable repeated tuning against known test data.

The new test file contains 46 collected cases; the existing suite contains 67, giving 113 cases for the supplied package versions.

| Checks | Purpose |
|---|---|
| Valid partition and non-mutation | Accept an appropriate synthetic table without altering it. |
| Chronological bounds, wrong horizon, reversed/duplicate rows | Detect incorrect or crossing forecasting examples. |
| Measurement age, exact age endpoints, source-age consistency | Reject stale/future readings; accept readings exactly zero or five minutes old. |
| Missing columns, incorrect count, invalid targets and clock fields | Detect unsupported data rather than silently remove rows. |

| Validation-only selection | Reject train/test score rows, unequal row counts, duplicate model names and invalid errors. |
| Tie handling and relative MAE reduction | Verify deterministic selection and distinguish error reduction from percentage accuracy. |
| Zero baseline error | Return undefined relative change instead of dividing by zero. |

These tests use synthetic data with known expected behaviour. Existing tests continue to cover the error calculations, persistence, time/day encoding, linear workflow, SVR pipeline and input validation.
