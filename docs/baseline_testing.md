# Baseline implementation checks

## Scope

`tests/test_evaluation.py` verifies only the shared persistence and metric functions.
It does not yet test chronological preparation, feature encoding, regression fitting,
SVR scaling or final model-selection procedures. It is not evidence of useful forecasting
accuracy or HVAC benefits.

## Test rationale

- Known persistence outputs: predictions equal current counts, including zero.
- Input isolation: changing a prediction must not mutate the supplied counts.
- Known metric example: observed `[3, 5, 10]`, predicted `[2, 7, 8]` gives
  MAE = 5/3 and RMSE = sqrt(3).
- Exact forecasts return zero error; zero observations are valid.
- Fractional and negative raw regression predictions are evaluated without silently
  rounding or clipping. A physical-output policy will be a separate modelling decision.
- Empty inputs, mismatched lengths, multidimensional arrays, missing values and
  infinities are rejected instead of producing misleading scores.

## Run locally

From the project root:

```powershell
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest tests/test_evaluation.py -v --junitxml=docs/baseline_test_results.xml
```

The XML is generated by the local test run. Commit it with this explanation after checking
that all tests pass. Do not describe these checks as full project validation.

MAE and RMSE calculations follow the definitions in MMA3001 Week 5.5. Model validation
separately compares predictions with later sensor-reported targets, using the reserved
chronological data partitions.
