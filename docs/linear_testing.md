# Linear-regression implementation checks

## What this addition changes

- `notebooks/4_linear_regression.ipynb` fits an ordinary least-squares model using only
  the training examples, then scores training and validation against persistence.
- `src/features.py` provides one fixed encoding of the five agreed inputs for both
  regression models. It does not learn averages, fit a model, or read targets.
- `tests/test_features_and_linear.py` tests the encoding and the intended fit/predict
  sequence with synthetic data. Existing `src/evaluation.py` and its tests are unchanged.

The initial representation uses three count columns, a daily sine/cosine pair and six
weekday flags. These are project-specific starting choices, not a proven optimal
encoding. Monday is the reference weekday. No rounding or clipping is applied to model
outputs. The extra numerical columns are derived from the same five agreed inputs.

## Why these tests exist

| Check | Purpose |
|---|---|
| Column names, order and row alignment | Prevent mismatching the input rows and targets |
| Known clock values and midnight continuity | Check the daily sine/cosine calculation |
| Weekday flags and reference day | Ensure labels are encoded consistently |
| Added target columns have no effect | Avoid accidentally giving future outcomes to the model |
| Encoding one row alone or in a batch is identical | Confirm the encoding does not learn dataset statistics |
| Inputs remain unchanged | Avoid side effects on prepared data |
| Missing, invalid or non-finite values are rejected | Avoid silent deletion or misleading predictions |
| Known synthetic linear relation | Verify the encoded-input/fit/predict workflow against a known answer |
| Prediction leaves fitted weights unchanged | Verify that the usage does not train on validation rows |

These checks do **not** prove that real sensor counts are correct, that future occupancy
is predictable, that all leakage paths are impossible, or that HVAC energy savings
will follow. They are not full coverage of the data-preparation workflow. Predictive
performance is evaluated separately using the fixed historical partitions.


21 new encoding/workflow checks. The XML file is generated by the local run. Do not edit
